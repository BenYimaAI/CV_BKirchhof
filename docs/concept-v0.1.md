## 3. Audience and visitor journeys

1. **Executives / hiring decision-makers:** Hero → leadership summary → 3 measurable achievements → manufacturing transformation thesis → downloadable public CV → contact.
2. **Engineering leaders / collaborators:** Technology filters → selected case studies → problem / method / decision / outcome / evidence → contact.
3. **Strategy / manufacturing peers:** Perspectives → public research sources → explicit hypotheses → proposed actions / metrics.
4. **Mobile readers:** Readable 30–90-second route with short summaries, sticky navigation and progressive disclosure.

## 4. Information architecture (proposed)

- **Home:** Profile photo, clear professional title, signature philosophy, 3 anchor proof points, CTAs.
- **Experience:** Clickable 2010–present timeline, filter by technology (ICE/BEV/eDrive/AI), geography and responsibility.
- **Impact:** Selected quantified case studies, verified results separated from future targets; technical explanations for readers who want depth.
- **Transformation Lab:** Engineering automation, production-data dashboards, Copilot/agentic workflows, knowledge management; demonstrate only scrubbed or synthetic datasets.
- **Perspectives:** Original articles on industrial competitiveness, localization, quality/cost/time, supplier strategy, resilience and market/technology shifts.
- **About / Leadership:** Motivation, leadership principles, education, awards, technical credentials, personal development.
- **Contact / Download:** Public PDF, professional links, email contact; do not publish mobile number without explicit approval.

## 5. Design directions

**A — Executive Editorial (recommended base):** warm white, dark graphite/navy, subtle teal/copper accent, highly legible headlines, portrait, long-form editorial readability. Serious without feeling bureaucratic.

**B — Manufacturing Intelligence:** rich interactive timeline, data cards, process diagrams, case-study comparison; more demonstrative but risks dashboard overload.

**C — Cinematic Industrial:** large production photography, careful motion and immersive case studies; attractive but slow and harder to maintain.

**Recommendation:** A as default, with restrained B components for project evidence. Avoid heavy 3D, gimmicky animations, stock photography or a copied corporate visual identity.

## 10. Technical delivery proposal

**Preferred:** Astro for statically generated HTML, modular content collections and selectively hydrated interactions. CSS design tokens and minimal client JavaScript; no app server required for public MVP.

**Hosting:** GitHub Pages through GitHub Actions or appropriate controlled hosting; public site never contains restricted content in its generated assets.

**Authoring:** Markdown/JSON initially; optional approved Notion content DB and build-time publishing integration after governance is defined. Never expose Notion secret tokens in browser source.

**Quality bar:** mobile-first; responsive layout (320px–wide desktop); no horizontal scroll in standard content; semantic HTML; target WCAG 2.2 AA; reduced motion; keyboard navigation; focus states; accessible images; validated internal navigation/downloads; asset compression; versioned content. Performance targets LCP <=2.5s, INP <=200ms, CLS <=0.1 based on Google Core Web Vitals field guidance, not guaranteed before launch.

**QA:** Playwright Chromium/Firefox/WebKit coverage and mobile emulation; screenshot regression tests; axe-core accessibility checks; link audits; privacy/confidentiality checks; CI approval gate before deploy. Automated a11y checks are partial and need human review.
